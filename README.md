# FitTune iOS 自适应训练 v1.1.1

FitTune 是一个本地优先的科学自适应力量训练原型，面向没有急性伤病、医生未禁止运动的成年人。

## 已完成

v1.1.1（构建 12）在保留旧记录和进行中草稿的基础上升级；新计划默认 4 个正式组，热身组独立计算，训练实时活动、FIT 3 心率广播、记录检索和重量输入均得到完善。

- 新生成和新增动作默认 4 个正式组且可修改；热身组不再占用正式组数量，旧历史与进行中训练保持原样。
- 灵动岛在力量休息时显示倒计时，展开可开始下一组；有氧显示持续计时、心率、距离或步频；结束、放弃和无草稿重启都会清理残留活动。
- HUAWEI WATCH FIT 3 开启标准心率广播并首次选择后，可在力量/有氧开训时自动扫描重连；Apple Watch 与 BLE 仍保持单一实时来源。
- 心率峰值、60/120 秒恢复、数据来源、覆盖率、区间、缺口及其对休息/下组建议的保守影响写入训练总结和历史。
- 无全天主动能量实测时，从步行热量估算中扣除有氧场次累计步数；全天步数显示不变。
- 底部新增“记录”页，统一检索力量与有氧并打开完整详情；删除、回收与恢复仍集中在“我的”。
- 重量输入支持点按全选、临时清空、键盘完成、长按连续加减，以及建议/上组/上次/最近重量快捷值。

- 六种主目标：减脂保肌、增肌、身体重组、最大力量、健康体能、恢复训练。
- 可选次目标，且次目标不会覆盖主目标。
- 六档训练经验，包括停训后恢复和 App 自动评估。
- 全身、上下肢、推拉腿三分化、胸背肩腿四分化与智能安排，可生成 2–6 天力量计划。
- 每个训练日按“主项、辅助项、收尾”分组，可在专用编辑页拖动排序、跨阶段移动、添加、删除和替换；取消不落盘，完成后原子保存。
- 每天先自主决定“今天训练”或“今天休息”；休息不会推进计划轮转。
- 今日可临场选择按计划推荐、胸、背、肩、腿、推、拉或全身，并可多选需要避开的部位。
- 力量与有氧是两个独立模块，可分别选择增肌/力量与减脂/基础有氧/心肺表现目标。
- 今日恢复状态：睡眠时长、睡眠质量、酸痛、压力和训练意愿，并保存长期恢复趋势。
- 首组建议重量读取上次同动作/同模式训练、距上次间隔、次数、RIR、动作质量与今日恢复。
- 逐组记录重量、次数、RIR、动作质量与疼痛；下组重量仅依据次数、RIR、恢复与历史生成，始终可手动覆盖。
- 动作替换使用完整目录与可解释评分，综合动作模式、肌群、阶段、器械、难度、收藏和近期记录；训练进行中已开始动作锁定，未开始动作仍可调整。
- 内置目录超过 220 个规范动作，覆盖杠铃/EZ 杠、哑铃、史密斯、插片/配重固定器械、绳索、蝴蝶机、罗马椅、壶铃、地雷管、弹力带和徒手；旧名称与收藏通过别名迁移。
- 训练中可增加、移除、替换动作，也可提前保存为“部分完成”，保留已做内容但不推进计划轮转。
- 训练草稿每次输入都会本地持久化；切换 App、锁屏或进程被系统结束后，重开会自动回到未完成训练。
- 主动退出训练页时提供“继续未完成训练 / 保存并结束 / 放弃训练”，放弃需二次确认。
- 今日热量按静息、力量、有氧、日常步数/步行和其他 Watch 主动消耗分项计算；步数与全天主动能量不会重复计数。
- Apple 健康中的静息心率、步数、步行距离和全天主动热量在 App 启动、回到前台及 HealthKit 观察通知后自动刷新，并显示来源、样本时间、同步状态和可信度。
- 静息代谢按实测 RMR、Cunningham 去脂体重、Mifflin–St Jeor 的顺序选择，并显示方法、置信度和区间。
- 力量/有氧运动能量按设备实测、速度/坡度、平均心率、MET 分层回退；未戴手表可先估算，之后用 Watch 数据匹配并更新原记录。
- 训练中可增加/移除动作，也能直接键入或加减当前动作的重量、次数、RIR 和计划组数。
- 有氧的时长、距离、速度、坡度、功率、楼层、平均心率、session-RPE 和设备热量均支持直接键入与加减。
- 动作库扩展并按胸、背、肩、腿、手臂、核心及杠铃、哑铃、史密斯、固定器械、绳索、徒手/弹力带分类。
- 当前组以醒目的“第 N / 总组数组”显示，区分热身组和正式组；用户设定的总组数优先级最高。
- 每组完成后按热身/正式、动作模式、次数、RIR、前组次数变化、恢复与历史 e1RM 生成 60–300 秒的可解释休息范围；计时可延长或跳过。
- 取消重复的“本组后感受”步骤；保留动作质量和疼痛/异常不适作为独立安全输入。
- 每个动作全部组完成后显示完成动画，明确提示下一动作。
- 极限 RIR、动作质量下降、疼痛或低恢复只会显示醒目安全建议，不自动结束、跳转、锁定或减少用户计划组数。
- 有氧可选择爬坡走、楼梯、游泳、跑步、骑行、划船、椭圆机、快走和跳绳；支持手动数据或 Apple Watch / 健康同步。
- 每次力量与有氧训练都会生成训练负荷、疲劳分、恢复范围和建议，不再用伪精确单点表示恢复。
- “我的”提供记录管理与回收站，可恢复误删记录，也可经二次确认后永久删除单条或清空回收站。
- 进展页的体重、主力动作 e1RM、心肺指标与恢复趋势统一保留近 30 天视图。
- 异常疼痛安全拦截。
- 训练记录、体重趋势、按动作 e1RM、12 分钟跑/走距离、VO₂ max、静息心率、睡眠与恢复趋势。
- Apple 健康体重读取入口。
- 全部个人数据默认保存在本机 `UserDefaults`，无账号、无服务器、无广告 SDK。
- Apple Watch 配套 target 可采集训练心率、步频、距离、能量和游泳划水，并与 iPhone 共享同一训练 ID；标准 BLE 心率设备可作为另一种独占实时来源。
- iPhone 开始训练后可请求 Watch 自动开训并等待场次确认；错误场次、重复、乱序、过期与累计值回退的数据包会被拒绝，断连时训练不中断而降级估算。
- 锁屏实时活动显示当前动作/组次、心率和组间休息倒计时，点击可返回未完成训练。
- 训练详情可仅清除心率/设备曲线而保留训练，导入的 Apple 健康/华为健康本地副本也可单独清除。
- JSON 完整备份与 CSV 分表导出；热量、恢复和训练效果都显示来源、可信度、合理区间与算法版本。
- 规则引擎单元测试。

## 运行

1. 使用 Xcode 26 或更新版本打开 `FitTune.xcodeproj`。
2. 选择 `FitTune` Scheme 和任意 iPhone Simulator。
3. 点击 Run。

模拟器通常没有真实 Apple 健康数据；其余功能可完整使用。若在真机运行，请配置唯一 Bundle Identifier、开发团队和 HealthKit 能力。首次运行会逐项请求只读健康权限；拒绝任一指标不会阻止训练，仍可使用手动输入或估算。

命令行验证：

```sh
xcodebuild -project FitTune.xcodeproj \
  -scheme FitTune \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=NO test
```

## 科学与安全边界

规则以渐进式抗阻训练、训练量、RIR 自我调节、跨训练日恢复和并行力量/有氧证据为方向。具体负重变化、60–300 秒休息范围与恢复分阈值是可审计的保守工程规则，不是适用于所有人的精确生理公式。研究只支持大致范围与调节因素，因此建议始终可修改或忽略。

能量与恢复计算依据详见 [`docs/scientific-basis.md`](docs/scientific-basis.md)。热量、训练效果和恢复小时数均是个体估算，不等于间接测热、实验室测试或医疗建议。

FitTune 不是医疗器械，不用于诊断、治疗、康复处方或替代医生/合格教练。出现尖锐疼痛、胸痛、眩晕、异常气短、麻木或动作突然失控时，应停止训练并视情况寻求专业帮助。

## v1.1 平台说明

- 当前仍采用 Codable + UserDefaults 的离线快照存储；本版本没有虚构 SwiftData 或云端迁移，JSON 导出可作为完整备份。
- 华为 FIT 3 不提供 FitTune 可直接使用的实时心率通道；应用通过其写入 Apple 健康的数据事后校准，无法取得的字段保持“不可用”，不伪造数值。
- HealthKit 后台观察由 iOS 调度，静息心率、步数和全天能量不承诺逐秒到达；Apple Watch 活跃训练会话才是高频实时路径。
- Apple Watch 与标准 BLE 心率设备同一时间只能占用一个实时来源；华为/HealthKit 事后导入不抢占实时连接位。
- Apple Watch 功能已提供源代码和独立构建目标；没有 Watch 硬件时以跨目标构建和状态机测试作为发布门槛，购买设备后仍需做硬件验收。
- 后续可升级 SwiftData、动作教学媒体和 TestFlight 运动专业人员复核，不影响 v1.1 离线训练。
