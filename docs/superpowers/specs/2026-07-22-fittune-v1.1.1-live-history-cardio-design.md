# FitTune v1.1.1 训练生命周期、心率与记录体验设计

日期：2026-07-22  
目标版本：`1.1.1 (12)`  
上一规则版本：`1.1-plan-edit-health-sync-1`

## 1. 目标

本版本修复并完善六类直接影响训练使用的问题：

1. 新计划动作默认只有 2 组，且现有模型把热身组计入总组数；
2. 训练结束后 Live Activity/灵动岛可能残留，紧凑状态不能持续看到休息倒计时；
3. 有氧训练不能自动取得 HUAWEI WATCH FIT 3 的实时心率；
4. 有氧训练内步数与全天步数在无全天主动热量时可能重复估算能量；
5. 完整训练记录入口隐藏较深，有氧缺少可打开的完整详情；
6. 训练中的重量不容易整段替换，常用重量需要反复点击加减。

本版本继续遵守以下不变约束：本地优先、离线可训练、任一传感器缺失只降低可信度、建议不能擅自结束动作或训练、历史计划快照不可变、Apple Watch 与标准 BLE 心率设备同时只能有一个实时来源。

## 2. 已确认的产品行为

### 2.1 正式组与热身组

- 新生成计划、新添加动作默认 `4` 个正式组，用户可在计划和训练中修改。
- 当前可编辑计划中少于 4 个正式组的动作一次性升级到 4 组；原本不少于 4 组的动作保持不变。
- 历史训练记录、历史计划快照和已经开始的训练草稿不迁移组数。
- 热身组与正式组彻底分开。2 个热身组加 4 个正式组表示总共完成 6 组，而不是从 4 组中占用 2 组。
- 训练界面分别显示“热身第 1/2 组”和“正式第 1/4 组”。主要训练量、力竭率、e1RM 与力量进步仍只使用正式组。
- 用户设定的正式组数是最高优先级；RIR、心率或疲劳建议不能删组或提前结束动作。

### 2.2 Live Activity 与灵动岛

- 力量训练正常阶段的紧凑灵动岛显示实时心率；没有可靠心率时显示当前正式组进度。
- 组间休息时紧凑区域优先显示倒计时。展开状态同时显示当前动作、心率、休息倒计时和“开始下一组”。
- 点击“开始下一组”会验证训练 ID 和草稿阶段，结束休息、进入下一组，并打开 FitTune 当前训练界面。
- 有氧训练紧凑状态持续显示训练时间；展开状态显示实时心率，以及运动类型支持的距离、步频或踏频。
- 完成、部分保存或放弃力量/有氧训练时，传感器和对应 Live Activity 走同一个结束流程，并使用立即移除策略。
- App 启动或恢复时枚举系统仍存在的 FitTune Live Activity：有对应有效草稿则恢复更新，没有对应草稿则立即结束，清理进程重启前遗留的灵动岛。

Apple 文档说明 `.immediate` 会在活动结束后立即移除界面；因此残留不能只依赖进程内保存的单个 `Activity` 引用，而要使用系统活动集合进行恢复和清理：[`ActivityUIDismissalPolicy.immediate`](https://developer.apple.com/documentation/activitykit/activityuidismissalpolicy/immediate)、[`Activity.end(_:dismissalPolicy:)`](https://developer.apple.com/documentation/activitykit/activity/end%28_%3Adismissalpolicy%3A%29)。

### 2.3 FIT 3 与实时心率

- 用户已确认其 HUAWEI WATCH FIT 3 支持“心率广播”。智能心率测量本身不等于向第三方 App 广播。
- 用户在手表开启心率广播后，FitTune 使用标准 Bluetooth Heart Rate Service 扫描、连接和读取；FitTune 无法从 iPhone 远程开启华为手表的广播开关。
- 用户首次选择 FIT 3 后，本机保存首选设备标识。以后力量或有氧开始时先尝试恢复该设备，再自动扫描匹配；不要求每次进入“设备与实时数据”重新选择。
- 如果广播未开启、设备不可达、连接中断或样本异常，训练继续并明确显示估算模式；恢复广播后只重连原首选设备，不抢占其他来源。
- Apple Watch 或标准 BLE（包括广播中的 FIT 3）只允许一个实时来源。华为健康事后写入 Apple 健康的数据不占实时连接位。
- 华为官方说明必须在设备“设置 → 心率广播”开启后，第三方设备和应用才能连接；没有该选项的设备不支持。部分单连接设备广播时可能暂时断开华为运动健康：[`华为手表/手环心率广播`](https://consumer.huawei.com/cn/support/content/zh-cn15827504/)。

### 2.4 心率如何参与力量建议

- 下一组重量的基础仍来自完成次数、RIR、四维恢复和同动作历史。
- 可靠实时心率作为保守限制信号：恢复不足、异常偏高或回落缓慢时阻止加重或建议减重；恢复良好只能解除限制，不能单凭心率提高重量。
- 下一组次数同样保持用户可改。恢复不足时可建议使用目标次数区间下限或减少次数，但不能自动覆盖输入。
- 组间休息直接使用动作类型、RIR、次数下降、主观恢复、峰值心率，以及组后 60/120 秒心率下降幅度。心率恢复较慢只能延长建议，不能缩短到证据区间以下。
- 心率缺失、过期、突跳或接触不良时不进入计算，建议退回无传感器算法并降低可信度。
- 任何建议只改变提示，不改变用户计划组数，不自动完成、跳过或结束训练。

### 2.5 心率记录与训练总结

力量和有氧记录保存以下内容：

- 去重后的心率时间序列、时间戳、实时设备来源、置信度和有效性；
- 平均心率、最大心率、有效数据覆盖率和个体化心率区间分布；
- 力量训练每个正式组结束后的峰值、60 秒与 120 秒心率恢复；
- 心率对下一组休息、重量和次数建议产生的限制、调整与原因；
- 样本中断、异常跳变、接触不良和估算降级区间；
- Apple Watch、FIT 3/标准 BLE、HealthKit 事后修订或手机估算的数据来源。

训练总结和历史详情展示心率曲线、平均/最大心率、区间分布、组后恢复、训练负荷、数据覆盖率和“哪些建议受心率影响”。用户仍可只删除心率/设备曲线而保留训练、动作和组记录。事后 HealthKit 修订采用追加总结修订，不改写原始组记录。

### 2.6 有氧步数去重

- “今日步数”始终显示 HealthKit/手机取得的全天总步数，其中自然包含有氧期间的步数。
- 每次有氧内的步数是自训练开始后的累计值。计算该场训练步数时取同一场次、同一来源的最大累计值，不能把每个采样点相加。
- 多次有氧分别取最大累计值后求和，得到“已计入有氧的训练步数”。
- 只有在缺少全天主动热量、必须用分项估算时，步行能量才使用 `max(全天步数 − 已计入有氧的训练步数, 0)` 对应的比例；全天显示步数不变。
- 如果存在 HealthKit 全天主动热量，它仍是主动能量总值。力量、有氧和步行只解释构成，绝不再次相加。
- 扣除值不能超过全天步数。来源不兼容、覆盖不足或训练步数缺失时扩大估算区间，并显示推导来源。

### 2.7 独立训练记录页

- 底部导航增加“记录”，与“今天、计划、进展、我的”并列。
- 默认按时间倒序统一展示力量和有氧；提供“全部/力量/有氧”和“全部/7 天/30 天”筛选。
- 搜索同时匹配力量训练名称、动作名称和有氧方式。
- 每一行显示类型、名称、日期、完成状态、时长，以及力量组数或有氧距离/心率摘要；点击整行直接打开详情。
- 力量详情继续展示计划快照、组明细和完整总结；有氧新增对应详情，展示时长、距离、步频/踏频、能量、心率曲线、数据来源和完整总结。
- 无记录或筛选无结果时提供明确空状态。
- 删除、永久删除和回收站恢复仍集中在“我的 → 管理与恢复记录”，记录浏览页不混入危险操作。

### 2.8 重量输入

- 训练中的重量改为专用大号输入面板，不再使用窄的通用数字行。
- 点击重量数字进入编辑时自动全选；允许编辑过程暂时为空，不在每个字符变化时把数值强制成 0。
- 数字键盘提供“完成”。提交时才解析、限制到合法范围并按需要规范小数；非法或空文本恢复最近一次有效重量。
- 保留减号和加号，步长使用个人负重增量，并支持按住连续增减。
- 提供“系统建议”“本动作上次重量”和最近 2–3 个不同重量快捷项；点击只覆盖当前组重量，仍可再次修改。
- 任何直接输入、快捷项或加减操作均标记为用户覆盖建议，但不改变计划模板，除非用户之后明确保存到模板。

## 3. 架构与数据模型

### 3.1 组数语义兼容

`ExercisePrescription` 增加可选的明确正式组字段。新计划和迁移后的当前计划写入该字段；旧记录和旧活动草稿缺少该字段时继续使用旧的“总组数”语义。这样可以同时满足：

- 新训练按“热身 + 正式”完成；
- 已开始的旧草稿不在恢复时突然增加组数；
- 历史快照解码和展示不变；
- 下一次架构升级后不再依靠字段名猜测语义。

新草稿使用计算属性统一得到正式组数、热身组数、总计划组数、当前阶段序号和是否完成。业务代码不能再直接用旧 `sets` 判断新草稿结束。

### 3.2 统一训练生命周期

增加一个可测试的生命周期协调层，输入是当前力量/有氧草稿、实时传感器状态和 URL 动作，输出是：

- 应启动、更新、恢复或结束哪个 Live Activity；
- 应开始、恢复还是结束哪个实时设备会话；
- 深链接是否与当前训练 ID、休息阶段和下一组条件匹配；
- 结束后需要持久化何种最终状态。

视图只发送用户意图，不各自拼接结束步骤。`WorkoutActivityController` 枚举 `Activity<FitTuneWorkoutAttributes>.activities`，而不是只依赖当前进程内的 `activity` 属性。

### 3.3 Live Activity 内容状态

内容状态增加训练类型、阶段、组次、休息结束时间、训练开始时间、心率、距离、步频/踏频以及当前训练 ID。Widget 根据类型和阶段选择最小信息集合。倒计时和有氧计时使用系统时间视图，避免每秒从 App 推送更新。

“开始下一组”使用包含训练 ID 的 `fittune://workout?action=startNextSet&session=<UUID>`。App 处理 URL 后重新读取本地草稿并校验，不信任 URL 自带状态。

### 3.4 首选实时设备

本地快照增加首选实时来源描述，只保存设备标识、种类、显示名称和最后成功时间，不保存健康样本。蓝牙层支持：

1. 按系统标识恢复已知外设；
2. 恢复失败后扫描标准 Heart Rate Service；
3. 只自动选择与首选设备标识相同的设备；
4. 超时后进入估算，但继续低频等待同一设备恢复；
5. 用户明确切换来源时才替换首选项。

### 3.5 心率建议轨迹

为每次组后建议保存轻量、可审计的决策记录，包括组 ID、生成时间、有效心率窗口、60/120 秒恢复值、基础建议、心率限制后的建议、原因和算法版本。原始心率曲线仍保存在训练 metric samples 中，决策记录用于训练总结解释，不重复存储曲线。

### 3.6 步数分摊

建立纯函数式步数分摊器，输入全天步数和当天有氧记录，输出全天步数、训练内步数、非训练步数和可信度。能量引擎只消费非训练步数对应的步行估算；记录和 UI 仍可展示原始总步数与各训练步数。

### 3.7 统一历史索引

力量与有氧记录映射为只读 `TrainingHistoryItem` 展示模型。它只包含筛选、排序和列表摘要所需字段，并保留原始记录 ID 与类型。详情页再按 ID 从 AppStore 获取最新的本地记录，避免复制或修改历史对象。

### 3.8 重量编辑状态

重量面板使用独立字符串草稿和最后有效数值。解析、范围限制、负重步长与最近重量提取放在可单测的纯逻辑中；SwiftUI 焦点、全选、键盘工具栏和长按重复只负责交互。

## 4. 迁移与版本

- App 快照 schema 从 `13` 升级到 `14`。
- 训练规则版本更新为 `1.1.1-live-history-cardio-1`。
- 能量算法版本更新，记录“训练内步数已从额外步行估算扣除”的新规则。
- schema 14 迁移只改当前可编辑计划和新增的设备偏好/组数语义字段，不改历史记录、历史计划快照或活动草稿。
- 当前计划每个动作的明确正式组数写为 `max(旧预设组数, 4)`；用户以后可自由改回 1–3 组。
- 迁移幂等：同一快照重复恢复不能反复增加组数或重复创建 Live Activity。

## 5. 异常与安全处理

- Live Activity 深链接的训练 ID、阶段或草稿不匹配时，只打开 App，不改变训练。
- 完成、部分保存和放弃均尝试结束本地及系统枚举到的匹配活动；即使 ActivityKit 失败，训练记录仍必须保存。
- FIT 3 未广播、超时、断连、心率过期、突跳或接触不良时不参与建议，UI 显示具体降级原因。
- 实时心率只能延长休息、阻止冒进加重或建议更保守的重量/次数，不能单凭心率提高重量。
- 有氧步数无法与全天来源可靠匹配时，扣除值采用保守上限并降低可信度，不能产生负步数或负能量。
- 重量输入无效时保留上一次有效值，不能因为键盘中间状态写入 0 kg。
- 所有健康和设备数据默认留在本机；用户可清除曲线、设备数据或整次训练记录。

## 6. 验收与测试

### 6.1 自动测试

- 新生成、新添加动作默认 4 个正式组且可修改。
- 2 个热身组 + 4 个正式组总共完成 6 组；只统计 4 个正式组。
- schema 13 当前计划迁移到 4 个正式组，历史和活动草稿字节语义不变，重复迁移幂等。
- RIR 0、心率恢复慢或主观恢复差都不能减少用户正式组数。
- Live Activity 快照在训练、休息、有氧三种状态产生正确紧凑/展开字段。
- 无草稿时清理遗留活动；有草稿时恢复；完成、部分保存和放弃立即结束。
- 深链接只有匹配当前休息草稿时才能开始下一组，重复和过期链接无副作用。
- 首选 BLE 来源被记住、自动重连、超时降级，且不能抢占另一活动来源。
- 心率恢复慢能延长休息、阻止加重或降低次数建议；心率良好不能单独提高重量。
- 心率曲线、覆盖率、平均/最大值、组后恢复和决策原因进入总结及记录详情。
- 有氧累计步数取每场最大值而非采样求和；多场汇总后从额外步行估算扣除且不超过全天总步数。
- 有全天主动热量时仍不重复加入力量、有氧或步行分项。
- 记录索引按类型、日期和名称/动作搜索，点击映射到正确力量或有氧详情。
- 重量文本支持整段替换、暂时为空、非法回退、快捷重量去重和连续步长调整。

### 6.2 构建与真机验收

1. 全量 `swift test` 通过；
2. iOS Release、Widget/Live Activity 和独立 watchOS target 构建通过；
3. 覆盖安装 `1.1.1 (12)`，不卸载旧 App；
4. 验证 schema 13 当前计划升级、历史记录仍可打开；
5. 力量训练完成一组后切换应用，紧凑灵动岛显示休息倒计时；展开后点击“开始下一组”回到正确训练；
6. 完成、部分保存和放弃各验证一次灵动岛立即消失；杀进程后验证遗留活动清理；
7. 有氧锁屏/切应用后计时继续，展开显示可用心率和运动指标；
8. FIT 3 开启心率广播，在“设备与实时数据”首次选择后验证力量和有氧自动重连、实时心率、断连降级和恢复；
9. 完成力量与有氧后验证心率曲线、组后恢复、建议原因和数据来源出现在总结及“记录”详情；
10. 验证今日总步数不变，而无全天主动热量时的额外步行能量扣除了有氧训练步数；
11. 验证重量全选输入、键盘完成、建议/上次/最近重量快捷项和长按加减。

## 7. 明确不在本版本内

- 绕过华为手表设置或私有协议，从 iPhone 远程开启 FIT 3 心率广播；
- 把 FIT 3 当作 Apple Watch 使用 HealthKit 实时 Workout 通道；
- 云账号、跨设备云同步或服务器推送 Live Activity；
- 用心率自动增加重量、自动删除组或自动结束训练；
- 重写为 SwiftData 或改变既有 JSON/CSV 导出兼容性。
