# FitTune v0.7 力竭默认、动作收藏与华为健康数据设计（已被替代）

> 本设计已并入并由 `2026-07-21-fittune-v1-live-training-design.md` 替代；保留本文仅用于追踪设计演进。

## 目标

在 FitTune v0.6 基础上，将新训练计划和每组输入的默认 RIR 统一为 0；扩充并重新整理动作目录；新增可持久化的动作收藏，让新生成的计划在动作模式和器械兼容时优先选择收藏动作；通过 Apple HealthKit 检测并导入华为运动健康 / HUAWEI WATCH FIT 3 实际写入 iPhone 的可用数据。

## 全局原则

1. 用户已明确选择默认每组训练至力竭，因此计划 `targetRIR` 和新组的 RIR 输入默认为 0。
2. 疼痛、异常不适与动作质量仍是独立安全输入；力竭默认不取消安全警告，也不授权算法自动结束、减组或锁住用户输入。
3. 收藏只能在相同动作模式、目标肌群和可用器械范围内提高选择优先级，不得为了使用收藏动作而改变训练部位或动作模式。
4. FitTune 不直连华为手表蓝牙，不使用未审批的华为云端接口。唯一自动数据通路是 `WATCH FIT 3 → 华为运动健康 → Apple 健康 → FitTune`。
5. 只有 Apple 健康中实际存在且用户授权 FitTune 读取的数据才会导入；不得把估算值标记为手表实测。
6. 本地 v0.6 历史记录必须继续可解码，已完成组的原始 RIR 不修改。

## RIR 默认与迁移

- `TrainingEngine.prescription` 为均衡、增肌和最大力量计划统一生成 `targetRIR = 0`，不再因经验等级改为 2–4。
- 开始训练、替换动作、进入下一动作和进入下一组时，当前 RIR 输入均初始化为 0。用户仍可直接改为任意 0–10。
- 首次从 v0.6 恢复时，现有计划处方的 `targetRIR` 迁移为 0。活动训练草稿的未完成当前组输入迁移为 0，草稿和历史中已完成的 `SetResult.rir` 保持原值。
- RIR 0 仍会使组间休息建议增加 60 秒，但算法输出仍限定在 60–300 秒。

## 动作目录与分类

保留 `MovementPattern` 作为计划和替换的安全边界，新增更细的 `ExerciseSubcategory` 供界面展示和检索。层级为：

`ExerciseCategory（肌群） → ExerciseSubcategory（动作类型） → EquipmentKind（器械） → ExerciseOption`

子类型至少包含：

- 胸：水平推、上斜推、下斜推、夹胸/飞鸟。
- 背：垂直拉、水平划船、直臂下拉。
- 肩：推举、前束、中束、后束。
- 腿：深蹲/股四头、单腿、髋铰链/臀、屈膝/腿后侧、小腿。
- 手臂：肱二头、肱肌/锤式、肱三头。
- 核心：抗伸展、抗旋转、屈曲、负重行走。

必须增加并正确归类：哑铃前平举、哑铃弯举、哑铃锤式弯举、负重引体向上、对握高位下拉、窄握高位下拉、反手高位下拉、泽奇深蹲和颈前深蹲。目录不得出现规范化后的重名、重复稳定 ID 或“A + B”组合动作。旧名称作为 alias 指向唯一规范动作。

## 动作收藏

- `AppSnapshot` 新增可选的 `favoriteExerciseIDs: Set<String>?`，`AppStore` 恢复旧快照时默认为空集。
- 收藏使用 `ExerciseOption.id` 而非显示名保存，避免名称调整时失效；迁移时丢弃已不存在的 ID。
- `AppStore.toggleFavoriteExercise(_:)` 立即持久化，并提供 `isFavoriteExercise(_:)`。
- 训练中的“更换动作/器械”和“增加训练动作”目录顶部先显示符合当前筛选条件的收藏，每个动作行提供独立星标按钮。
- “计划”页新增收藏动作管理入口，允许不开始训练也能浏览、筛选和收藏。
- `TrainingEngine.generatePlan` 和非“按计划推荐”的当日临时组训接收收藏 ID；对每个所需 `MovementPattern`，先从器械兼容的收藏动作中选择，再回退到现有器械优先级。
- 收藏变更不改写已开始的训练，也不立即覆盖已手动定制的存量计划。它对下次“保存并重新生成计划”和新组装的临时训练生效；界面明确告知这一点。

## 华为 Watch Fit 3 / Apple 健康数据通路

### 能力检测

`HealthKitService` 新增“检测可穿戴数据”查询，请求读取：

- 步数、步行+跑步距离、主动能量。
- 静息心率、心率样本。
- 睡眠分析。
- `HKWorkout` 训练记录及其平均心率、距离和主动能量。

查询结果按 `HKObject.sourceRevision.source.name` / `bundleIdentifier` 与 `HKDevice.manufacturer` / `model` 标识来源。不将数据限死为某个未公开的华为 bundle ID；来源名、制造商或型号包含 `Huawei` / `华为` 时标记为华为数据，其他来源仍可作为 Apple 健康通用数据导入。

界面不再仅显示“同步 Apple Watch”，改为“同步手表 / Apple 健康”，并显示检测报告：数据类型、最近时间、来源名、是否成功导入。若 Apple 健康中只有华为步数/距离，就只导入这两项，心率、能量、睡眠与训练显示“未检测到”。

### 静息心率与恢复

- 新增按日保存的 `RestingHeartRateEntry`，包含日期、bpm、来源、是否实测与原始 HealthKit UUID。以 UUID 防止重复导入。
- 当日存在实测静息心率时，与过去 21 天内、不含当日的个人中位数基线比较。至少 7 个有效日才计算急性偏离；样本不足时只显示数值，不调整恢复分。
- 偏离阈值是透明、可测试的保守工程规则：当日高于基线 5–9 bpm 时从恢复分扣 5 分；高于基线至少 10 bpm 时扣 10 分；不因低于基线而额外加分。这不是医疗阈值，也不单独决定是否训练。
- 没有当日实测值时，按近 21 天中位数 → 最近一条历史 → `UserProfile.restingHeartRate` 的顺序生成低置信度估计。估计值参与恢复卡展示和计划说明，但因无法表示当日急性变化，对恢复分保持中性（不加不减）。
- 调整后的恢复分继续通过现有 `ReadinessAssessment.loadMultiplier` 影响首组和下组重量建议、休息建议和恢复文案。它不自动改写动作、用户计划组数或 RIR 输入。
- 训练心率样本只用于训练平均心率、强度和能量计算，不能冒充静息心率。

## 数据流与错误处理

1. 用户点击同步，`HealthKitService` 请求必要读取权限并并行查询各类数据。
2. 服务返回结构化 `WearableHealthImport` 和每类 `WearableSourceStatus`，不再使用位置容易出错的多参数 completion。
3. `AppStore.importWearableHealth(_:)` 合并步数、能量、有氧/力量训练和静息心率，以 UUID 或现有 external ID 去重。
4. 权限被拒绝时显示“请在设置 → 健康 → 数据访问与设备中允许 FitTune 读取”，不清空旧数据。
5. 华为运动健康未向 Apple 健康写入某类数据时，报告显示对应缺失项和设置路径，其余类型仍正常导入。

## 测试与验收

### 自动化测试

- 所有训练目标的 `targetRIR` 为 0，新建草稿和推进下一组后 RIR 输入为 0。
- v0.6 快照恢复后，计划和未完成组迁移为 RIR 0，已完成历史组不变。
- 用户指定的新动作全部存在且归属正确肌群、子类型、动作模式与器械。
- 目录 stable ID 唯一、规范化名称唯一、无组合动作；旧 alias 正确解析。
- 收藏集可编码/解码，切换收藏后重建 `AppStore` 仍保留。
- 器械和动作模式兼容时，计划优先选收藏；不兼容的收藏不进入计划。
- 实测静息心率样本足够时，偏离正确调整恢复分；无当日数据时返回历史估计且不调整分数。
- 同一 HealthKit UUID / external ID 重复导入不产生重复记录。
- 华为来源判定同时支持英文和中文来源名，未知来源不误标为华为。

### 模拟器与真机验收

1. 模拟器验证收藏、分类、RIR 0 和旧快照迁移。
2. 使用原 Bundle ID 覆盖安装到用户 iPhone，不卸载、不清空数据。
3. 在真机点击“同步手表 / Apple 健康”，请求权限后检查华为来源。这一步可能需要用户在 iPhone 的健康权限页确认授权。
4. 若存在静息心率，验证来源、时间、bpm 和恢复说明；若不存在，验证显示历史估计和低置信度，不生成伪实测记录。

## 科学与产品边界

默认每组 RIR 0 是用户的明确训练偏好，不表示论文证明所有动作、所有组和所有训练者都应训练至力竭。FitTune 必须在科学说明中持续区分“用户选择”与“证据支持”。

静息心率是非特异性恢复信号，可受感染、脱水、药物、咖啡因、测量时间和设备等影响。它只能在个人基线上小幅调整恢复分和建议置信度，不可单独作为医疗判断、伤病诊断或强制停训依据。
