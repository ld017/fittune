# FitTune v1.1.1 Live Training Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship FitTune `1.1.1 (12)` with four editable working sets plus separate warmups, reliable Live Activity lifecycle and controls, automatic FIT 3 BLE reconnection, heart-rate-aware conservative recommendations and summaries, cardio-step energy de-duplication, a first-class history tab, and faster weight entry.

**Architecture:** Preserve schema-13 history and active drafts while adding explicit working-set semantics to schema 14. Put lifecycle decisions, heart-rate recovery, step allocation, history indexing, and weight parsing behind pure/testable types; keep SwiftUI and ActivityKit/CoreBluetooth adapters thin. Strength and cardio share one lifecycle path, one exclusive live sensor source, and provenance-aware summaries.

**Tech Stack:** Swift 5, SwiftUI, ActivityKit/WidgetKit, CoreBluetooth, HealthKit, CoreMotion, XCTest, Codable + UserDefaults, Xcode iOS/watchOS targets.

## Global Constraints

- Target iOS 17+, watchOS 10+; no new third-party dependencies.
- App snapshot schema becomes `14`; rule version becomes `1.1.1-live-history-cardio-1`; marketing version/build become `1.1.1 (12)`.
- Existing history, plan snapshots, and an already-active schema-13 workout draft must not change meaning.
- New and newly added exercises default to four working sets; warmups are additional and both values remain user-editable.
- Heart rate may extend rest, prevent an increase, or recommend lower load/reps; it must never independently increase load or delete/finish sets.
- Daily step display remains total steps. Workout steps are removed only from fallback walking-energy estimation.
- FIT 3 requires the user to enable HR broadcast; missing sensors degrade without blocking training.
- Health data stays local and metric curves remain separately deletable.
- Implement every behavior through a failing test first and commit each task independently.
